# שיעור 12: עדכונים ושדרוגים
**מעבדה מעשית (תרגול לתלמיד) (גרסת vEXP)**

## מטרת התרגול
תרגול שליטה בעדכוני מערכת (Updates ו-Upgrades) באמצעות ממשק המשתמש (GUI), הבנת מנגנון ה-RSR (Rapid Security Response) דרך הגדרות המערכת, ותרגול תהליך העברת נתונים נכון באמצעות Migration Assistant בסביבה ארגונית.

---

## תרגיל 1: ניהול עדכוני תוכנה בממשק המשתמש הגרפי

> **מה לומדים:** להבדיל בין Update (טלאי קטן) ל-Upgrade (שדרוג ראשי) ב-GUI, לאמת הגדרות RSR ולהבין מדוע macOS דורש שטח פנוי גדול בהרבה ממשקל העדכון עצמו.

**תרחיש:** עליכם לוודא שהמערכת מעודכנת, להבין היכן מופיעים עדכוני מערכת מינוריים (Updates) לעומת שדרוגים מלאים (Upgrades), ולוודא שעדכוני אבטחה שקטים (Rapid Security Responses / BSI) מוגדרים להתקנה אוטומטית כפי שנדרש בארגון.

### שלב א': איתור עדכונים זמינים

1. פתחו את אפליקציית **System Settings** (הגדרות המערכת).
2. נווטו אל **General** (כללי) ולאחר מכן בחרו ב-**Software Update** (עדכוני תוכנה).
3. המתינו מספר שניות בזמן שהמערכת מחפשת עדכונים בשרתי אפל.
4. שימו לב לחלוקה במסך:
   * **עדכונים מינוריים (Updates):** יופיעו בחלק העליון (למשל מעבר לגרסה 26.1). אלו טלאים קטנים יחסית.
   * **שדרוגים גדולים (Upgrades):** יופיעו בחלק התחתון בנפרד (למשל המלצה לשדרוג ל-macOS חדש לגמרי). ההפרדה נועדה למנוע התקנה בטעות על ידי המשתמש.

### שלב ב': הגדרת עדכונים אוטומטיים ו-RSR

1. באותו מסך, לחצו על כפתור המידע (סמל ה-**i**) הממוקם לצד השורה של **Automatic Updates**.
2. יוצגו בפניכם מספר מתגים חשובים. ודאו שהמתג הבא דולק:
   **Install Security Responses and system files**
3. **משמעות ארגונית:** הפעלת מתג זה קריטית. היא מאפשרת ל-macOS לקבל עדכוני אבטחה דחופים, שמגיעים כקפסולות (Cryptex) ומוחלים על המערכת (לרוב ללא צורך באתחול ארוך), וכן לעדכן את רשימות החתימות הזדוניות (XProtect) המובנות.
4. בסיום הבדיקה, לחצו על **Done**.

### שלב ג': הורדת שדרוג מלא (Upgrade) דרך ה-Terminal

לעיתים נרצה להוריד את קובץ ההתקנה המלא (Installer) כדי ליצור כונן USB להתקנה או לפרוס אותו למחשבים אחרים בארגון.

1. פתחו את אפליקציית ה-**Terminal**.
2. הריצו את הפקודה הבאה כדי למשוך את קובץ ההתקנה העדכני ביותר:
   ```bash
   softwareupdate --fetch-full-installer
   ```
   *(במידה ותרצו להוריד גרסה ספציפית תוכלו להוסיף `--full-installer-version 26.0`)*
3. פעולה זו תוריד את קובץ ההתקנה לתיקיית ה-Applications שלכם כקובץ בשם `Install macOS [Name].app`. (תוכלו לעצור כעת את הפעולה בעזרת `Control + C` במידה ואינכם רוצים לסיים את ההורדה הכבדה).

## תרגיל 2: הדמיית העברת נתונים (Migration Assistant)

> **מה לומדים:** כיצד Migration Assistant עובד, אילו נתונים מומלץ להעביר, ומדוע בסביבה ארגונית הגישה Clean Slate עדיפה להעברה מלאה.

**תרחיש:** המשתמש קיבל Mac חדש. עלינו להעביר את החומר שלו בצורה נכונה מבלי לדרוס חשבונות (Local Account) או לייצר כפילויות במערכת.

!!! warning "תזכורת"
    בסביבות מנוהלות (MDM) מומלץ להימנע מהעברת נתונים מלאה באמצעות כלי זה, כיוון שהוא עלול להעביר פרופילי תצורה ישנים ואפליקציות שבורות.

### שלב א': הכנות והפעלת הכלי

1. פתחו את **Migration Assistant** מתוך התיקייה `/Applications/Utilities` (או בעזרת Spotlight).
2. הכלי יבקש את סיסמת מנהל המערכת (Admin) ויסגור את כל שאר האפליקציות. אשרו זאת.
3. במסך הראשון, בחרו באפשרות של **From a Mac, Time Machine backup, or startup disk** ולחצו על **Continue**.
4. *בסימולציה זו:* אל תמשיכו לבצע העברה בפועל (כדי לא לאתחל ולהשבית לכם את המערכת), אך הכירו את האפשרויות הבאות.

### שלב ב': בחירת הנתונים להעברה (Best Practices)

1. כשהכלי מזהה מקור, הוא מחשב את הנפח ומציג רשימה: `Users`, `Applications`, `Other Files & Folders`, `System & Network`.
2. **כללי אצבע למניעת תקלות:**
   * פתחו את רשימת החשבונות וסמנו **רק** את חשבון המשתמש הרלוונטי. 
   * **המלצה ארגונית חזקה:** הסירו את הסימון מ-`System & Network` כדי למנוע העברת הגדרות רשת ישנות שעלולות להתנגש עם ה-MDM.
   * הסירו את הסימון מ-`Applications` כדי להימנע מהעברת Kexts בעייתיים או תוכנות שתלויות ב-Rosetta 2 שאינן מעודכנות ל-Apple Silicon.

### שלב ג': ניהול התנגשות חשבונות (UID Conflict)

1. אם ב-Mac החדש כבר קיים חשבון בעל שם משתמש **זהה** לזה שאתם מנסים לייבא, הכלי יתריע על התנגשות (Account Conflict).
2. האפשרויות:
   * **Replace:** מחיקת החשבון הקיים ב-Mac החדש ודריסתו המלאה.
   * **Keep both user accounts:** המערכת תשנה את שמו של החשבון המיובא כדי לייצר הפרדה (למשל, תוסיף "1" לשם המשתמש) – מה שמוביל לבלבול אצל העובדים.
3. צאו מהאשף כעת בצורה מסודרת (`Quit`).

## תרגיל 3: חקירת מנגנון Rapid Security Response (RSR)

> **מה לומדים:** לזהות גרסת RSR מותקנת, להבין מה האות בסוגריים מסמנת, ולדעת כיצד לבצע Rollback אם העדכון שבר תאימות עם תוכנה ארגונית.

**תרחיש:** בתור מנהלי IT, תרצו לוודא איזה גרסת RSR מותקנת כעת וכיצד ניתן לבטל אותה (Rollback) במקרה שהעדכון שבר תאימות עם תוכנות פנימיות של החברה.

1. פתחו את **System Settings** ונווטו אל **General -> About**.
2. בדקו את שורת ה-macOS. אם מותקן כעת טלאי RSR מהיר, תראו אות בסוגריים (למשל `(a)`) לצד מספר הגרסה (כגון `macOS 26.3.1 (a)`).
3. לחצו על כפתור המידע (סמל ה-**i**) שלצידה.
4. במסך שייפתח מופיע כפתור ה-**Remove** שנועד להסיר את עדכון האבטחה (פעולה שתבטל את טעינת ה-Cryptex באתחול הבא של המערכת, ותחזיר אתכם לגרסת ה-SSV הבסיסית).
