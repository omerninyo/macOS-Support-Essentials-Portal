## מעבדה: ניהול APFS, פתרון תקלות ב-Spotlight וחקר Clones

### מטרת המעבדה

ללמד את הסטודנטים לעבוד עם הכלים המובנים של macOS (ממשק משתמש וטרמינל מתקדם) כדי לנתח חלוקת מקום דינמית, לחקור Firmlinks, להתמודד עם בעיות מקום פנוי שגוי באמצעות Spotlight, לאמת את הגדרות האבטחה (SSV) עבור כלים ארגוניים, ולהבין את הקסם של מנגנון ה-Clones.

### תרחיש

> משתמשת פונה אליכם ומתלוננת: *"מחקתי המון קבצים אבל המחשב עדיין אומר שאין לי מקום בגלל System Data עצום, ובנוסף, המחשב בקושי מתפקד כשמעתיקים קבצים גדולים!"*. באותו הזמן, איש ה-IT מבקש מכם לאשר שהמערכת מאובטחת לפני פריסת אנטי-וירוס ארגוני.

## שלב 1 — הכנת כונן העבודה האישי (USB)

> **מה לומדים:** APFS Container ו-Volume בפועל, ו-Dynamic Space Sharing.

בקבלתכם לקורס קיבלתם כונן USB. נשתמש בו כסביבת הניסויים שלנו כדי לא לסכן את כונן המערכת האמיתי ולמנוע בעיות של `fsck_apfs` (Failure to unmount) העלולות לצוץ בבדיקת כונן חי.

1. חברו את כונן ה-USB שלכם ל-Mac
2. פתחו את תוכנת **Disk Utility**
3. בשורת התפריטים: **View → Show All Devices**
4. אתרו בצד שמאל את הכונן הפיזי החיצוני שלכם
5. לחצו על **Erase**
6. בחרו:
   - **שם:** `StudentDrive`
   - **פורמט:** APFS
   - **סכמה:** GUID Partition Map
7. לחצו **Erase** ← אשרו

כעת יש לכם Container ו-Volume. לחצו על ה-Container הראשי וראו כיצד הוא מציג את חלוקת המקום.

## שלב 2 — יצירה וניהול Volume דינמי ב-APFS

> **מה לומדים:** Volumes גדלים ומתכווצים בדינמיות — אין צורך להגדיר גודל מראש.

1. בחרו בצד שמאל את כרך **`StudentDrive`** ב-Disk Utility
2. לחצו על סמל **(+) Volume** בשורת הכלים העליונה
3. קראו לו **SharedPool**
   - אפשר ללחוץ על Options ולהגדיר Quota למקרי קצה — לצורך התרגיל לחצו **Add** בלבד
4. שימו לב כמה מהר הוא נוצר! לחצו עליו וראו שהמקום הפנוי שלו **זהה לחלוטין** לזה של ה-`StudentDrive`

> [!NOTE]
> שניהם חולקים את אותו המאגר — זוהי Dynamic Space Sharing בפעולה. אין כאן מחיצה "שייכת" לאחד מהם.

## שלב 3 — חקר SSV ו-Firmlinks (למחלקת ה-IT)

> **מה לומדים:** SSV חוסם כתיבה לכונן המערכת. Firmlinks הם "התפרים" שמחברים את שתי המחיצות.

נחזור למערכת המקומית כדי לענות לאיש ה-IT:

**3.1 — הוכחת חסימת SSV:**
```bash
sudo touch /System/test.txt
```
*(שגיאת `Read-only file system` מוכיחה שה-SSV חתום וסגור)*

**3.2 — אימות חתימת האבטחה:**
```bash
csrutil authenticated-root status
```
*(הסטטוס `enabled` = אין צורך לסרוק את מחיצת המערכת נגד וירוסים)*

**3.3 — חשיפת ה-Firmlinks:**
```bash
cat /usr/share/firmlinks
```
*(שימו לב לנתיב `/Applications` המאחד בין קבצי קריאה-בלבד לנתוני המשתמש)*

> [!TIP]
> כשאיש ה-IT שואל "האם אנחנו צריכים לסרוק את מחיצת המערכת?" — הפקודה בשלב 3.2 היא התשובה הרשמית.

## שלב 4 — טיפול באשליות מקום (בניית Spotlight מחדש)

> **מה לומדים:** "System Data" מוגזם לרוב הוא אינדקס Spotlight מושחת — לא קבצים אמיתיים.

הפתרון המומלץ לבעיית ה-"System Data" של המשתמשת:

1. פתחו **System Settings → Siri & Spotlight → Spotlight Privacy...**
2. גררו את **Macintosh HD** פנימה ← לחצו **Done**
   *(פעולה זו מוחקת את מסד הנתונים הישן)*
3. היכנסו שוב לאותו מסך — הסירו את הכונן
4. פתחו **Activity Monitor → טאב CPU** — חפשו `md`

תהליכי `mds_stores` או `photoanalysisd` יזנקו. המחשב בונה את האינדקס מחדש!

> [!NOTE]
> אם התהליך לוקח ימים — Runaway Indexing — יש להניח לו לסיים אלא אם מבודדים קובץ ספציפי בעייתי ב-Safe Mode.

## שלב 5 — חקר APFS Clones (אפקט הוואו)

> **מה לומדים:** Clone = עותק מיידי ללא תפיסת מקום — עד לביצוע שינוי.

**5.1 — העתקה רגילה (לשם השוואה):**
1. העתיקו קובץ וידאו כבד אל **StudentDrive**
   *(פעולה זו תיקח זמן כי מבוצעת כתיבה פיזית לכונן החיצוני)*

**5.2 — שכפול בשבריר שנייה:**
1. ב-Finder, בתוך `StudentDrive` — סמנו את הקובץ
2. הקישו `Cmd + D` (שכפול)
3. השכפול קורה **מיידית!** ← Finder השתמש אוטומטית ב-Clone

**5.3 — הוכחת Zero-storage בטרמינל:**
```bash
du -h /Volumes/StudentDrive/*
```

> [!IMPORTANT]
> הקובץ המקורי ישקול את משקלו המלא. הקלון ישקול **0B**. זה לא באג — זו תכונת APFS.
